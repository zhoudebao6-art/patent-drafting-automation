# 提效执行索引

运行过程只有一条主线：来源准备→初稿→独立复查→必要修改后独立重验→逐案交付。16/8/8是三个并行工作池，不是每案再启动多套审查。模型、来源边界、六项和全部当前页覆盖保持；只删重复读写、导航及无关步骤。当前详细机械契约统一放[快速执行](fast-execution.md)，本页不再重复一份带历史版本补丁的操作手册。

## 正常批次

1. 按[批处理流程](batch-workflow.md)识别来源并init一次，冻结工具和规则；环境每批预检一次，首次配置、依赖变化或新故障才做小样。普通办案不跑技能回归、检查GitHub或通读历史案例。
2. 按[CLI池](cli-workers.md)使用实际可用容量持续补位；手工通道直接reserve --prepare。总控可以本地预提取即将开始的下一案，不先处理整批资料，不为提取占模型槽。
3. worker直接使用CLI提示中已完整提供的阶段包，未内嵌时才按分块读一次；prepared直接交接来源/当前稿缓存、导航和页面候选；公式与附图按math_guide场景索引补读。来源提取及数学完整性不是因压缩指令而省去的工作。
4. 初稿核内容和公式后用公共生成器，复用其有效inspection；修改集中处理findings及关联内容。review首轮集中列问题，后轮按[增量回执](worker-receipt.md#v626-增量复查)核变化与依赖，保留有证据的未受影响通过范围。
5. 内容稳定才渲染，已有同稿页面先验身份；全部当前页须由实查和有效继承覆盖。通过即提交一次回执并交付桌面同一批次目录，不等整批，不另加模型或打包台账。

## 按需深入

|需要处理的问题|唯一详细入口|
|---|---|
|快照、规则读取、来源导航和公共生成|[快速执行](fast-execution.md#新批次一次准备)，来源缓存字段见[数据契约](data-contracts.md#批次记录)|
|预检/渲染复用、证据和回执字段|[回执规范](worker-receipt.md)、[运行环境](runtime.md)；prepared候选不是验收通过|
|收稿、一次机械收尾、历史审计|[快速执行](fast-execution.md#收稿与交付)|
|三池补位、慢I/O与单写交付|[三池执行](three-stage-pools.md)、[CLI池](cli-workers.md)|
|内部故障接续|[工具故障恢复](tool-fault-recovery.md)|

缓存核来源/工具/选项身份及产物哈希，变更或损坏须重建；不同案例不共用可写目录。渲染指纹绑定稿件、工具、配置和字体，不能因命中缓存认定显示正确。工作工具路径用prepared或--help，返回实际路径不猜目录结构。已授权案件的内部工具缺陷可直接修复验证，恢复先收已有结果，不重复收费重放。

## 速度口径

以每小时十件独立验收后实际交付的新终稿为目标。按[快速执行的统计口径](fast-execution.md#速度统计)在批次结束或用户要求时运行batch_throughput.py，不加入逐案流程。区分冷启动和稳定队列；缺资料、限流和真实复杂度如实记录，不外推短窗口或降低验收。

保留16/8/8和模型强度时，十件/小时对应每案累计初稿96分钟、复查48分钟、修改48分钟的池容量预算，含重验；它不是硬超时，不据此终止正常工作或自动通过。优先减少返工和无关阅读，不再添加协调器或缩短已达0.2秒的池唤醒。文字减少、本地I/O或合成测试只能报告各自范围，未经真实完整窗口验证不宣称达标。

## 大份证据按字段查询

已知inspection字段路径时直接调用冻结脚本，例如`evidence_query.py inspection.json --section field --field issues --field media --offset 0 --limit 30`。多字段共用本次报告字节和SHA，每个字段返回自己的total和next_offset。仅续读尚有下一页的字段。未知路径先用默认summary查看available_fields；字段不存在与空数组明确区分，不将零候选记为通过。公式仍用`--section formulas --ids 对象ID`保留完整OMML，段落用既有part/start/end范围；来源正文仍须按实际审阅范围读取content。不要整份打印inspection、公式/术语台账或无关历史。

同稿渲染先验证后复用；新渲染优先输出到当前DOCX父目录下的render目录，使既有prepare_handoff能够直接发现。已有合法路径保留，不能为了目录约定搬移旧证据或修改旧SHA。主控只收取和交付，不添加已通过稿的第二次格式审查。

## 本轮延迟修复

容量恢复沿原事件日志读取一次，不为升载另发模型探针；后续真实完成触发补位预算恢复。同稿转换完成后只恢复交接，不重建相同页面。预览疑点先按QA-09定位原始单页或局部，确认为显示层差异后继续原审查；变更范围、关联、失败及未审范围保持新会话独立复查，其他有效通过证据直接复用。
