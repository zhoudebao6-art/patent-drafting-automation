# 所述、公式来源与符号格式

本页执行规则 TXT-04、TXT-10、FORMULA-01 至 FORMULA-05；基础规则适用于版本6起，版本10补充[公式结构与版式标准](formula-layout-standard.md)。原用户反馈见[本轮要求](terminology-formula-user-requirement.txt)，历史依据见[定稿证据](terminology-formula-evidence.md)。当前用户要求优先于旧定稿中不一致的个别写法；不静默改写在途批次的冻结规则。

## 逐处核查所述后的完整名词

版本37按用户2026-10-16最新要求收紧：所述后面只能回指此前已作为独立对象引入的完整名词，不得使用两个汉字组成的名词。此处的独立指完整名词在句中明确命名同一对象，不是必须单独成句，也不要求特定引入动词；仅在另一长词、受限定对象或相似说法中包含这几个字，不构成独立引入。该要求是用户写作标准，不是法律结论。人工稿提供句法依据，新要求优先于其中不一致的旧例。

先核完整对象及独立前置，再核名词长度。所述动作、所述记录等两字名词即使曾独立出现也不采用；所述动作序列、所述动作执行状态等不能因为开头是动作而误判，仍须核对完整名称及真实前置。不得擅自补相关、相应等字凑成较长短语，也不得把单个动作改成动作集合来借已有名称。数学符号、名称和源技术事实不由此改写。

修正时优先沿用来源和当前合法前文已建立的完整名称，保留其限定条件和对象身份。确无完整前置时，用有来源的完整表述先引入，或在不会造成歧义时去掉多余所述；不能为了保留所述新增技术特征、扩大对象范围或造定义。前文存在执行量未确认的动作，不等于已独立命名不受限定的动作，不能据此机械通过所述动作。每次修正同步权项对应技术方案及相关引用，重新统计每项至少3处合法所述；数量要求不能压过前置和两字名词禁用。

先找每一处“所述”，再人工识别紧随其后的**完整技术名词或名词短语**，不能只截取第一个字、短词或句子余下全文。例如“所述参考轨迹位置”的被指对象是“参考轨迹位置”；此前仅出现“位置”“轨迹”或“参考轨迹”均不足以自动支持这个复合名词。

1. 按字符先后登记首次引入处：段落、权项、句内位置、完整名称和对象身份。首次引入不用“所述”；同一分句/句子中先引入，后半句再用“所述”可以成立。
2. 权项中的前置基础只取本项该位置之前及实际合法父项链。摘要、说明书、其他独立项、未引用的同级项和后文首次定义都不能补这个前置基础。多重引用的每条实际路径分别核对。
3. 名称相同仍核对身份；区分集合/单体、候选/已选、原始/修正、当前/历史。同义词只有已明确登记为同一对象时才可映射，禁止用子串命中或随意同义化通过。
4. “根据权利要求1所述的……方法”是权项引用头，单独核查引用和方法名称，不当成普通技术名词首次回指。另区分说明书“下文所述方式”等确有下文对象的行文指引，不把它作为权项前置基础。识别修饰边界：“所述A的B/所述A内的B”须按句义判断所述回指A还是完整复合对象，不能固定截到标点或只取最短名词。原稿正反边界见[正确稿话术](reference-style-standard.md)。
5. 对真正的新对象，最小修正通常只删除其前面的“所述”，保留名称和源技术内容。若它实际上必须承接另一项对象或缺少实质定义，删除“所述”也不能掩盖技术依赖缺口；依据来源修复并记录影响，无依据则列待确认。不得为了保留“所述”新增虚构步骤、定义或技术限定。
6. 后续名词可裸写，也可在前置与身份明确时用“所述”；不把每次重现都机械改为“所述”。发明内容去掉引用头后重新检查，实施方式也按自身行文先引入再回指；权项中的定义不自动豁免其他章节的首次行文检查。

版本16起同时执行每整项至少3处合法所述。跨该项所有自然段计数，合法引用头计入且单列；先核每处前置与身份，再统计有效数。数量不足只调整原有对象的复指和句子承接，不在新名词前强加、不添加来源没有的功能或定义。该门槛不扩展到其他章节；[人工定稿规范](manual-format-and-wording.md)说明样本差异和未满足时的处理。

用户截图的最小修正示例（前提：适用权项此前未引入该词）：

> 在保持参考轨迹位置的周期顺序的匹配路径中，选取对应单位方向夹角之和最小的路径，形成当前采样时刻与参考轨迹位置的对应关系，并保留当前采样时刻的原始时间间隔。

首处去掉“所述”，后处“参考轨迹位置”保留裸写即可。若原始上下文确有合格前置，则不凭截图片段机械删除。

在既有 terms.json 逐处记录 `following_noun_phrase`、`occurrence_locator`（含句内偏移）、`scope`、`introduced_at`、`ancestor_path`、`identity_evidence`、`verdict` 和 `correction`。版本37在同一记录补 `introduction_text`、`introduction_span`、`standalone_introduction`、`boundary_reason` 和 `two_character_noun`：保存前置的完整原句/名词范围，明确其为何独立指向同一对象而非较长词的子串，两个汉字完整名词不得通过。没有依据的引用不能记passed；引用头及行文指引分类另记reference_kind，实际名词范围记head_span。合法权项引用头所述的完整名称仍单独核查；下文所述方式等旧行文指引不能豁免两字限制，应据语义改为不含该短名词回指的自然表述。

inspect_docx.py在同一次提取中提供可提取正文、表格、文本框及页眉页脚等位置的所述上下文与偏移，并把两个汉字后接的或分隔符的情况标为`two_character_prefix_candidate`。这是有限的字面边界线索，不是自动分词，不能证明名词长度或前置合法；未提示也必须逐处核查，遇动作时间等完整长名词不能按前两个字替换。原始完整段落和权项树已在同一报告中，Sol/xhigh复用这些证据完成原antecedents检查，不新建模型阶段、不重复提取或增设一套审核。

## 先冻结来源公式清单，再撰写

公式只来自本项目已授权的技术优化书/说明书及明确补充资料。先通读正文、表格、普通文本公式、OMML、图片与嵌入对象，把每条来源公式连同位置和完整结构登记后确定 N。读取失败、图像不清或定义有歧义时标记待核定；“未检出 OMML”不等于零公式。

- `main_formula`：源材料中完整的计算、关系、约束或判定表达式，独立排版与行内排版均计入，应逐条对应到成稿完整公式。来源 N 条，成稿 N 条，不能新增、漏掉、将多条并成一条，或拆成更多条。复合公式的分组按原来源结构记录，不按排版换行机械计数。来源重复展示同一条时保留各次出现的来源记录并说明对应关系，不能自行去重降低 N。
- `symbol_reference`：只是已登记变量、下标、算子等的引用，不是另一个计算公式；同样需要来源与符号身份对应。
- `source_example`：源材料已有的数值代入演示，单列计数与映射，保持其原有公式表达数量，不得凭撰写需要新增。不能把新的计算关系改称“算例”来绕过 N。

N 是经语义分类的来源完整公式清单数，既不是 OMML 对象数，也不是 oMathPara 数。同时登记全部类别的源稿与成稿出现位置：每个成稿数学表达都要能回到来源。历史三案的4条主公式只是各自证据，不能变成新项目固定公式数。

源材料核查后 N=0 且无原有数值表达时，成稿也不得新增计算、关系或判定公式，连“说明性”“推导性”“通用定义”“示例阈值”等都不例外；以来源支持的文字说明即可。N>0 时同样不得新增推导式、等价展开式、损失函数、经验阈值或自行构造的数值代入。完整公式在其他章节需要再次提及时采用来源支持的文字指向，避免重复抄写增加完整公式出现数。按源逐条、按稿逐条双向核对，计数相等不足以证明没有“一增一漏”。

只对唯一有依据的笔误做一对一修正，保留原式、改式、理由和影响；不能自行改变技术关系或造式补洞。无法唯一核定的公式列为待确认，不通过删式或猜写凑齐数量。

## 完整符号及其格式

历史三个定稿的 OMML 数学 run 均明确为 **Cambria Math、14磅（w:sz=28）、正体（m:sty=p）**。复合公式和结构符号沿用这一基准，上下标尺寸由真实 OMML 结构控制。版本16起根据人工定稿，解释中无特殊字形语义的孤立变量允许普通宋体14pt正体基线run，不必套OMML；具体证据见[人工定稿规范](manual-format-and-wording.md)。中文说明沿用正文样式。此为用户指定样式，不是法定格式。

版本34按最新用户要求增加局部字号例外：同一条完整公式的显示续行合并成一行，14pt起始，必要时只缩小该式及分号，保留数学结构、语义字形和显式字号比例；正文解释不缩小。多条完整公式、矩阵、条件和求和限制不展开。最大可读字号、工具支持范围及最终单行验收按[版式标准](formula-layout-standard.md)，不以固定14pt强留不必要续行。

每个符号建立完整身份：基字符/Unicode、大小写、希腊或拉丁字母、上下标与顺序、帽号/横线等修饰、粗体/字形族、转置/共轭/逆的作用范围、括号、范数和矩阵结构。源中携带含义的字形/粗体不能因正体基准丢失；保留并记明来源。不要把 ℓ 改成 l/1，把希腊字母改成形似拉丁字母，把帽号估计量改成原量，或丢掉上标 H、⊺、−1、∗ 等。

公式确定的每个完整数学符号是该条解释的复用基准。带上下标、修饰或语义字形的符号优先复用对应OMML子树，保留同字形族和完整结构；不能以普通字母代替带下标的完整参数。只解释孤立的g、B等普通变量且身份/角色明确时，可用前述普通run例外；单独解释某下标的角色可在正文基线书写该裸字母，不删除公式中的真实下标。ℬ不能变B，向量粗体不能消失。普通文本拼接相同不等于符号相同，Cambria Math相同也不等于m:scr等属性相同。

不同公式中确有不同含义的同名符号须由来源区分，不能全局替换。历史高合金稿的转置 T→⊺ 有该案对应证据，并非所有项目的替换规则；H（共轭转置）等不能随意替代。历史地脚稿存在公式 A/D/T 与解释 script 字形不一致，不能继承这个缺陷。

## 公式内无真实空白

成稿公式以及说明中复用的数学符号片段内，不插入普通空格、全角空格、不换行空格、窄空格、制表/换行文本或零宽占位来拼排公式。对所有表示方式核对：OMML 的 m:t/w:t、普通文本公式、对象与图片公式。生成时去掉多余占位；成稿再扫描一次。

保留 OMML 分式、上下标、矩阵、括号、算子等结构和引擎自然数学间距；无真实空格不等于把所有符号挤在一起。XML 文件的排版缩进不属于公式内容；U+2061 等语义运算字符也不是填充空格。若删除空格会把两个变量拼成另一名称，按源数学结构表达乘积或算子，不能盲目拼接或凭空补“×”。无法确认原意时列待核定。m:brk 等强制排版断点也需核查是否多余，不自动破坏源有意义的分组。

inspect_docx.py 的 `math_evidence` 给出字面空白、显式字体/字号/数学属性及结构线索；未显式设置的属性标 null/空，需要核对继承样式和显示。脚本只自动扫描 OMML 内文本，普通文本/图片/OLE 仍由模型对照显示复查。零警告不是完整验收证明。

新增结构核对：空格可能是错误拼排的空基底/空限制，删除后仍不正确，须按源恢复完整限制位置。多行eqArr既可能只是显示续行，也可能承载求和、集合或分段条件；按[版式标准](formula-layout-standard.md)分类后处理，并记录脚本layout证据与处置。保留源语义不等于保留源文件的坏排版。

## 并入既有六项复查

版本39要求全部完整符号有文中解释：逐式核对左右两侧及嵌套部分，将每个完整量、参数、索引、集合、函数及算子关联本案含义依据和实际正文解释位置。基字或索引的解释不能代替带上下标、帽号、向量字形或实际参数的完整量；同基字不同身份分别核对，同身份同义量可复用已定位的解释。解释必须写在文件内容中，不能只存在于台账。遗漏、截短、未定义或含义无法据源确认时，formulas不得通过；依据明确的在原修改阶段补齐，无依据记未解决，不能删公式/符号或编含义。完整操作与工具边界见[全部完整符号解释](formula-detail-standard.md#版本39-全部完整符号解释)，复用现有formula_registry.symbols，不新增台账或模型轮次。
Sol/high 撰写前建立来源公式清单和首次术语登记，写完先做结构预检。Sol/xhigh 在既有 `antecedents` 检查逐处回指，在 `formulas` 检查源/稿计数、双向来源对应、完整符号及解释、无真实空白、格式与数学意义。其他四项照常执行，不另造并行验收通道。

review.json 的证据至少包含：逐处所述结论、N及全部分类计数、每个源/稿公式定位和映射、符号差异/空白发现与处理记录；并绑定最终文件哈希。数为零时也写明已检查哪些表示方式。未看清/未检查不能记 passed。全部修改由 Sol/xhigh 执行并重验，最后一次修改后重新渲染并逐页查看；通过后按既定规则逐案交付。

版本23按[文中符号与收尾](formula-layout-standard.md#版本23-文中符号普通算例和公式收尾)进一步区分普通正文变量、独立普通字母、数学结构和普通算例；源数值算例与标签可登记prose_example/prose_label并用文字输出，保持来源身份、字符和值，不能因对象数量下降改动主公式N。解释引导语用其中，独立大公式末尾一个分号。
