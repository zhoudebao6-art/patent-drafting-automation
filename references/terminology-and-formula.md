# 所述、公式来源与符号格式

本页执行规则 TXT-04、TXT-10、FORMULA-01 至 FORMULA-04；基础规则适用于版本6起，版本10补充[公式结构与版式标准](formula-layout-standard.md)。原用户反馈见[本轮要求](terminology-formula-user-requirement.txt)，历史依据见[定稿证据](terminology-formula-evidence.md)。当前用户要求优先于旧定稿中不一致的个别写法；不静默改写在途批次的冻结规则。

## 逐处核查所述后的完整名词

先找每一处“所述”，再人工识别紧随其后的**完整技术名词或名词短语**，不能只截取第一个字、短词或句子余下全文。例如“所述参考轨迹位置”的被指对象是“参考轨迹位置”；此前仅出现“位置”“轨迹”或“参考轨迹”均不足以自动支持这个复合名词。

1. 按字符先后登记首次引入处：段落、权项、句内位置、完整名称和对象身份。首次引入不用“所述”；同一分句/句子中先引入，后半句再用“所述”可以成立。
2. 权项中的前置基础只取本项该位置之前及实际合法父项链。摘要、说明书、其他独立项、未引用的同级项和后文首次定义都不能补这个前置基础。多重引用的每条实际路径分别核对。
3. 名称相同仍核对身份；区分集合/单体、候选/已选、原始/修正、当前/历史。同义词只有已明确登记为同一对象时才可映射，禁止用子串命中或随意同义化通过。
4. “根据权利要求1所述的……方法”是权项引用头，单独核查引用和方法名称，不当成普通技术名词首次回指。
5. 对真正的新对象，最小修正通常只删除其前面的“所述”，保留名称和源技术内容。若它实际上必须承接另一项对象或缺少实质定义，删除“所述”也不能掩盖技术依赖缺口；依据来源修复并记录影响，无依据则列待确认。不得为了保留“所述”新增虚构步骤、定义或技术限定。
6. 后续名词可裸写，也可在前置与身份明确时用“所述”；不把每次重现都机械改为“所述”。发明内容去掉引用头后重新检查，实施方式也按自身行文先引入再回指；权项中的定义不自动豁免其他章节的首次行文检查。

用户截图的最小修正示例（前提：适用权项此前未引入该词）：

> 在保持参考轨迹位置的周期顺序的匹配路径中，选取对应单位方向夹角之和最小的路径，形成当前采样时刻与参考轨迹位置的对应关系，并保留当前采样时刻的原始时间间隔。

首处去掉“所述”，后处“参考轨迹位置”保留裸写即可。若原始上下文确有合格前置，则不凭截图片段机械删除。

在 terms.json 逐处记录 `following_noun_phrase`、`occurrence_locator`（含句内偏移）、`scope`、`introduced_at`、`ancestor_path`、`identity_evidence`、`verdict` 和 `correction`。没有依据的引用不能记 passed；引用头分类另记。inspect_docx.py 提供全部“所述”的上下文与偏移，**不会自动分词或判定语义通过**，Astra/high 须对照完整段落和权项树核查。

## 先冻结来源公式清单，再撰写

公式只来自本项目已授权的技术优化书/说明书及明确补充资料。先通读正文、表格、普通文本公式、OMML、图片与嵌入对象，把每条来源公式连同位置和完整结构登记后确定 N。读取失败、图像不清或定义有歧义时标记待核定；“未检出 OMML”不等于零公式。

- `main_formula`：源材料中完整的计算、关系、约束或判定表达式，独立排版与行内排版均计入，应逐条对应到成稿完整公式。来源 N 条，成稿 N 条，不能新增、漏掉、将多条并成一条，或拆成更多条。复合公式的分组按原来源结构记录，不按排版换行机械计数。来源重复展示同一条时保留各次出现的来源记录并说明对应关系，不能自行去重降低 N。
- `symbol_reference`：只是已登记变量、下标、算子等的引用，不是另一个计算公式；同样需要来源与符号身份对应。
- `source_example`：源材料已有的数值代入演示，单列计数与映射，保持其原有公式表达数量，不得凭撰写需要新增。不能把新的计算关系改称“算例”来绕过 N。

N 是经语义分类的来源完整公式清单数，既不是 OMML 对象数，也不是 oMathPara 数。同时登记全部类别的源稿与成稿出现位置：每个成稿数学表达都要能回到来源。历史三案的4条主公式只是各自证据，不能变成新项目固定公式数。

源材料核查后 N=0 且无原有数值表达时，成稿也不得新增计算、关系或判定公式，连“说明性”“推导性”“通用定义”“示例阈值”等都不例外；以来源支持的文字说明即可。N>0 时同样不得新增推导式、等价展开式、损失函数、经验阈值或自行构造的数值代入。完整公式在其他章节需要再次提及时采用来源支持的文字指向，避免重复抄写增加完整公式出现数。按源逐条、按稿逐条双向核对，计数相等不足以证明没有“一增一漏”。

只对唯一有依据的笔误做一对一修正，保留原式、改式、理由和影响；不能自行改变技术关系或造式补洞。无法唯一核定的公式列为待确认，不通过删式或猜写凑齐数量。

## 完整符号及其格式

历史三个定稿的 OMML 数学 run 均明确为 **Cambria Math、14磅（w:sz=28）、正体（m:sty=p）**。按这一历史基准生成公式和说明中的数学符号；上下标尺寸由真实 OMML 结构控制。中文说明沿用正文样式。此为本技能的用户指定样式依据，不是法定格式。项目用户明确另定样式时记录覆盖。

每个符号建立完整身份：基字符/Unicode、大小写、希腊或拉丁字母、上下标与顺序、帽号/横线等修饰、粗体/字形族、转置/共轭/逆的作用范围、括号、范数和矩阵结构。源中携带含义的字形/粗体不能因正体基准丢失；保留并记明来源。不要把 ℓ 改成 l/1，把希腊字母改成形似拉丁字母，把帽号估计量改成原量，或丢掉上标 H、⊺、−1、∗ 等。

公式确定的每个完整数学符号是该条解释的复用基准。正文“其中，……”解释使用同一符号片段，优先复制对应 OMML 子树，保持同字体、同基准字号、同字形族和完整上下标/修饰，再定义全部参数、索引、算子与源条件。普通文本拼接相同不等于符号相同，Cambria Math 相同也不等于 m:scr 等属性相同。不能以普通字母代替带下标的完整参数；单独解释某下标/算子时明确其角色并保留它原有字形。

不同公式中确有不同含义的同名符号须由来源区分，不能全局替换。历史高合金稿的转置 T→⊺ 有该案对应证据，并非所有项目的替换规则；H（共轭转置）等不能随意替代。历史地脚稿存在公式 A/D/T 与解释 script 字形不一致，不能继承这个缺陷。

## 公式内无真实空白

成稿公式以及说明中复用的数学符号片段内，不插入普通空格、全角空格、不换行空格、窄空格、制表/换行文本或零宽占位来拼排公式。对所有表示方式核对：OMML 的 m:t/w:t、普通文本公式、对象与图片公式。生成时去掉多余占位；成稿再扫描一次。

保留 OMML 分式、上下标、矩阵、括号、算子等结构和引擎自然数学间距；无真实空格不等于把所有符号挤在一起。XML 文件的排版缩进不属于公式内容；U+2061 等语义运算字符也不是填充空格。若删除空格会把两个变量拼成另一名称，按源数学结构表达乘积或算子，不能盲目拼接或凭空补“×”。无法确认原意时列待核定。m:brk 等强制排版断点也需核查是否多余，不自动破坏源有意义的分组。

inspect_docx.py 的 `math_evidence` 给出字面空白、显式字体/字号/数学属性及结构线索；未显式设置的属性标 null/空，需要核对继承样式和显示。脚本只自动扫描 OMML 内文本，普通文本/图片/OLE 仍由模型对照显示复查。零警告不是完整验收证明。

新增结构核对：空格可能是错误拼排的空基底/空限制，删除后仍不正确，须按源恢复完整限制位置。多行eqArr既可能只是显示续行，也可能承载求和、集合或分段条件；按[版式标准](formula-layout-standard.md)分类后处理，并记录脚本layout证据与处置。保留源语义不等于保留源文件的坏排版。

## 并入既有六项复查

Sol/high 撰写前建立来源公式清单和首次术语登记，写完先做结构预检。Astra/high 在既有 `antecedents` 检查逐处回指，在 `formulas` 检查源/稿计数、双向来源对应、完整符号及解释、无真实空白、格式与数学意义。其他四项照常执行，不另造并行验收通道。

review.json 的证据至少包含：逐处所述结论、N及全部分类计数、每个源/稿公式定位和映射、符号差异/空白发现与处理记录；并绑定最终文件哈希。数为零时也写明已检查哪些表示方式。未看清/未检查不能记 passed。全部修改由 Astra/high 执行并重验，最后一次修改后重新渲染并逐页查看；通过后按既定规则逐案交付。
