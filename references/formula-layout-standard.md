# 公式结构与版式的通用执行标准

2026-10-14用户要求基于截图和三组历史定稿进行长期通用修正。本页落实FORMULA-04、FORMAT-01并补充FORMULA-02/03；源数学内容与显示排版必须分别核对。适用于后续新批次，不能静默篡改在途批次规则或把本页当成旧成稿已经修复的证明。

版本16按[人工定稿](manual-format-and-wording.md)补充正文/页眉样式及孤立变量普通run例外：不带结构或特殊语义字形的单字母解释可用宋体14pt正体基线；复合公式和带上下标/修饰的完整符号仍按本页数学结构规则。不得由该例外将全部公式转纯文本或丢失向量/集合字形。

## 实际问题与反例

RGB伽马项目源文件SHA256为`82e79a43150c6bc60246aa8d5c48dbcec246522afab5be8fc342d59ddad106c3`，P36与对应稿P58的主公式均为顶层`oMath/eqArr`两行，第一行只有左式及等号，第二行为双重求和积分。源文件已经包含这种显示分行；无`m:brk`或字面换行也会形成截图效果。源排版不能作为免修理由，但截图不足以证明数学关系错误，末端编辑光标不能当作要删除的公式符号。

三组历史源/定稿复核还发现：

- wearable源P33→定稿P84、alloy源P54→定稿P106：定稿把argmin限制放在空白基底的`sSub/sub`，`limLow/lim`却是空格。alloy定稿P146的min/max也有类似问题。仅删除空格会留下错误拼排，须依来源恢复完整限制到`m:lim`。
- 三定稿12条主公式虽居中，却带正文的`firstLine=560,firstLineChars=200`；新稿独立公式应清除这类首行缩进，两种计量属性均须处理。
- wearable定稿P117的`nary/sub/eqArr`是复合求和限制，bolt定稿P153和alloy定稿P146的`d/e/eqArr`是集合或逻辑条件。均不能因为多行而展开。
- bolt定稿P153与P154的A/D/T字形不一致不能继承。P137的`w:sym Symbol:00B1`不能在普通文本提取时漏掉，也不能将字体编码通用地按Unicode解释。

以上P为全部`w:p`顺序而非页码。六份历史原件身份见[source-manifest.json](source-manifest.json)，此前话术/主公式映射见[历史证据](terminology-formula-evidence.md)。这些是OOXML及上下文证据，不是六稿全篇视觉或数学通过证明。

## 写作时的处理顺序

1. 冻结完整源公式及符号身份。分别记录数学语义结构（操作数、分式、上下标、上下限、修饰、括号/矩阵）与显示结构（容器、行、缩进、字号）。完整公式N→N；重排同一公式的显示行不增加公式数，多条完整公式不能因同处一个eqArr而合并计数。
2. 对每个多行数组检查其祖先路径和每行内容，分类为显示续行、独立多式、求和/极值限制、集合/分段条件或矩阵。只有已核定为纯显示续行，才可在保留子树和次序的条件下重排。不能用拼接`linear_text`重建公式。
3. 版本34：已核定为同一条完整公式的显示续行合并成一行，包括首行已有完整左右式、后续行以加减号继续的情况。独立居中段、首行/字符首行/悬挂缩进归零，核对实际可用宽度。14pt是起始基准；必要时仅缩小该公式及同段收尾分号，选能完整放入一行的最大可读字号，通常依次试13、12、11、10.5、10、9.5、9pt。保留源内显式字号的比例、数学自然间距及语义字形，不删符号、不横向压扁、不改变正文或全篇页边距。
4. 同一条公式不能因为源稿已经分行就照搬续行；纯外层显示续行壳可移除，原数学子树按原序复制，不用linear_text重建。多条完整等式、嵌套求和限制、集合、矩阵与分段条件保留各自结构，不能为了单行而展开。9pt是公共工具的可读性保护下限，不是法定字号；达到下限仍越界或模糊时，记录具体排版阻碍并继续复查，不能继续盲缩或标通过。设置非裁切行高与必要同页控制，必须以最终页面确认实际单行、上下限完整且清晰；指定字号不等于已经适配。
5. 发现空基底上下标、空限制、空分母、缺操作数时，对照源树修复；禁止盲删空白后直接通过，也禁止自动补变量、界限或乘号。源也有多种解释时保持待核定。
6. 公式定型后，正文解释从同一规范符号片段复制。核对基字符、大小写、上下标顺序、帽/横线、粗体/字形族、转置/共轭范围及全文同对象出现处。中文用正文样式，数学片段用数学样式；不能仅靠字符串、字体名或相同对象数量判一致。

## 格式基准与来源优先级

|对象|本用户历史基准|必须核对的边界|
|---|---|---|
|正文|宋体14pt、左对齐、首行两字符|段落角色分别设置，不传播到公式/居中标题；项目明确要求可覆盖。|
|项目名称|宋体14pt、居中加粗|取消正文首缩进，不复制页眉模板编码。|
|说明书栏目|宋体14pt、左对齐加粗|看实际文字run及继承，不能只看段落标记格式。|
|复合公式及结构数学片段|Cambria Math、14pt起始基准、无语义区别的常规变量按正体|版本34允许同一条长式局部缩小到可读单行，正文解释不跟随缩小。源的向量粗体、script/双线体等有义字形优先保留；不能把所有`m:sty`置p。真实上下标由OMML缩放。孤立普通变量解释按版本16的正文run例外。|
|独立公式段|居中，无正文首行/悬挂缩进|明确清理`firstLineChars/hangingChars`等遗留属性；保留数学自然间距。|
|页面|三定稿A4纵向，历史上左约25mm、下右约15mm|是模板观察值，并非法定要求；以本案确认模板为准。|
|行距|没有证据支持全篇统一固定值|继承、网格、snapToGrid和公式高度一起看；不能设过小固定行高裁掉上下限或帽号。|

对数学run同时检查`m:rPr`及`w:rPr`、数学控制属性与文档mathPr，区分显式属性、有效继承和未知。缺属性不等于错误。常规斜体可按正体基准统一；有义粗体必须保留（例如源bi转换为b须确认仅改变斜体并同步解释，无法确认就保留原字形）。不要把标量分量与整个粗体向量混同。历史字体某些eastAsia槽仍为MS Mincho，不能照抄成统一基准。

## 预检与最终复查

继续使用同一`inspect_docx.py`，无需另起一遍全稿扫描。`math_evidence.layout`输出数组路径/行内容、空必需槽、显式断点/制表以及数学与Word直接样式冲突；段落`layout_evidence`保存直接缩进/行高/样式。诊断均为`needs_review`，不自动修改或判定公式正确。普通文本、图片、OLE与自动换行仍须人工核对。

以下代码是定位线索：`MATH_SINGLE_EQUATION_CONTINUATION`、`MATH_ARRAY_TRAILING_OPERATOR`、`MATH_EMPTY_SLOT`、`MATH_EXPLICIT_BREAK`、`MATH_STYLE_CONFLICT`、`MATH_FIXED_LINE_HEIGHT`、`MATH_DISPLAY_INDENT`。同次formula_prose_evidence记录single_equation_continuation_hits；已识别的单式纯显示续行必须修正，不能用source_math_identity豁免。结构复杂的候选仍须原语义复查，不猜合并。操作符单独引用等合法情况可依源关闭；不得把所有警告统一标忽略。继承的固定行高、字体替换、自动折行可能没有诊断，零诊断不等于合格。

Sol/xhigh在既有`formulas`检查中逐项保存来源位置、数组语义分类、变更前后结构及理由、完整符号与解释对照、诊断处置；`rendered_pages`记录最终页码及公式/符号实际显示。与最终DOCX哈希绑定，不新增平行验收流程。每条主公式及其解释查看足够清晰的原尺寸区域，同时查看整页，检查等号连续、上下限完整、横线/帽号、缺字/方框/问号、越界和分页；缩略拼图不能代替。必要时按用户使用的Word/WPS核对同一文件的显示，不能拿不同文件或删掉报错符号的PDF证明通过。修正后新复查模型独立重验，未核定问题不得记passed。
