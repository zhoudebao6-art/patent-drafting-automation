# 内部工具故障修复与接续

适用于已授权专利批处理中的可复现内部工具缺陷；不适用于把来源变动、模型身份不符、坏哈希或未知进程当作格式错误忽略。采用版本47后，停止新派发用于保全证据和避免重复收费，不要求总控停止诊断，更不自动产生额外批准步骤。正常任务不额外执行本流程。

1. 先保存失败日志和已有稿件，核对当前manifest、原worker进程、真实最终回执、源文件/快照及稿件哈希。继续收存其他已经运行的结果，不重启同案未知状态worker，不占用其他聊天的批次控制权。
2. 已确认内部缺陷时，先在技能维护副本完成最小修复，针对故障和误放行边界验证。保留原/新代码哈希、原因、测试结果及受影响文件；本来已授权任务中的这类可逆维护直接进行，不反复询问能否修工具。来源事实、模型强度、业务规则及六项验收不能借修复放宽。
3. 原skill-snapshot及旧reservation、dispatch、worker-final、completion、events/session、失败记录保持原字节。可给仍在原授权任务中的worker提供经过验证的隔离兼容helper，让它真实执行后输出自己的回执；该路径/哈希须记录，不能暗中换源快照或重写其原最终回复。未证实兼容的新版整个工具包不套入旧批次。
4. 优先沿原manifest收取有效真实回执并继续未完成阶段。已退出且最终回执无效、或已被判failed的attempt不能事后改成成功：使用具备身份/来源/稿件绑定及幂等检查的受控恢复入口，仅导入已核验候选初稿，派发新的独立review；没有受支持入口先据该故障实现并测试所需窄路径，不能手工改status/pass绕过。恢复仍执行原冻结模型、全部六项及当前稿最终页面；已经做出的有效初稿不重写。
5. 保持一个交付目标和通过一案立即交付一案。优先保留原批次和原delivery_path；必要恢复工作区属于内部，不是新桌面交付目录。尚无桌面成稿时，可由一个有来源绑定的恢复批次承接全部相关初稿并只产生一个最终目录。已有交付时，恢复入口须支持原目录的归属、文件和事务核验；不能另建第二个目录兜底，也不能改owner冒充同一事务。不移动用户文件或合并无关批次。

每个补丁对同一未解决故障只尝试一次恢复；复现原故障后保留状态，依据新证据修正或报告具体阻断，不盲重跑收费模型。只有继续工作确实需要用户提供材料、选择技术范围或授予现有授权之外的权限时才询问，明确缺什么；不能只因快照只读而要求再次批准普通工具修复。

## v6.19回执误判的窄修复

独立准备先封存pending预留，再准备handoff并生成ready job，原reservation不回写。assemble仅在原reservation SHA一致、当前attempt的prepared/handoff.json为独立常规文件、固定路径/封存SHA/context都相同时，回映preparation_state并扣除新增prepared_handoff后严格比较完整字典；任何其他身份、来源或未知字段变化均拒绝。该判断只证明正常准备转换，不能代替prepare/bind/record的来源和真实执行验证，也不证明专利内容通过。

本页规定总控处理方式，不声称运行池能够自动诊断任意异常，也不让worker自行修改共享工具。技能更新只改变以后冻结的工具；已运行故障由所属总控按上述证据边界接续，不能把安装成功当作旧批次已恢复。
