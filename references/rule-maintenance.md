# 持续优化

v5.0新批次冻结工具和规范，安装新版本只影响以后新建批次；不得修改已运行批次的skill-snapshot。新增规则按原维护流程应用后，未来init重新编译清单，核对原文instruction/check/exceptions/范围及全部active ID覆盖。清单是派生产物，不直接手改。规则涉及新字段或规范章节结构时同步stage_bundle及相应测试；不因一次纯话术修改重跑整个批次/渲染回归。

v5.7的lean模式允许已知纯主控global规则路由到worker-controller.md，其他适用/未知/project规则保持在worker原文包；核对两组不重叠且合并为全部active ID。五份原始写作规范与worker-standard.md由worker-standard-coverage.json绑定SHA；任一规范改变时，先核对执行要点和条件引用完整覆盖本次约束与例外，再更新覆盖文件并独立复核，不能只刷新哈希绕过覆盖审查。分块拼接必须与阶段清单一致；普通worker不重复读取完整库。

用户可直接说“更新技能”“按这个问题优化规则”“用这份新定稿继续优化”。用户于2026-10-13明确：“你做的所有的技能更新都是通用更新不是一次性更新”。因此技能更新默认长期、通用、持久生效，以当前实际调用目录为准，先读取版本。

## 收集和分级

用户要求的技能更新记 user、scope=global，并在核查后设为active；后续所有适用项目和新批次默认加载，无需再次确认是否长期生效。只有用户明确说“仅本项目/仅本次”时才记project覆盖。基于案例提出的技能纠错须提炼成跨项目可执行的检查或写作规则，不能写成只匹配该案例名称的特判。未获用户要求通用化、仅自行观察到的案例差异仍先candidate；项目名称、技术参数、公式内容和实验数据始终留在各自来源，不能当作全局技术事实。

摘录改前/改后及来源，明确替换哪条约束；阅读旧规则做语义冲突审查。用户说“更新技能”即已授权长期通用化，不再追问是否仅本次，也不额外要求“加入技能/以后如此”字样；单纯要求改一段稿件而未要求更新技能时，仍只改该稿。

参考其他技能的授权范围仅是提高效率：只看用户指定的提效部分，提炼并行补位、缓存、少读少写和恢复机制，不复制或加载其余业务内容。外部技能中的话术、模板、技术事实、模型分工、交付物和验收要求不成为本专利技能规则。更新时对照本次差异逐项核来源；发现越界引入则从现行入口、规则、提示和被调用资源中删除，并检查调用关系。保留本技能由用户TXT、三份正确稿及后续明确指令建立的专利要求，不因其他技能也有同类机制就误删。历史来源记录不构成运行指令，普通批次不重读外部技能或重跑这项维护审计；以后新增非效率借鉴须有用户对该内容的明确授权。

## 更新文件

用户2026-10-20明确授权从权利要求模板压缩包更新权项规则，属于指定的业务内容授权，不受上述其他技能仅借鉴提效的范围限制。只提取五模板的权项约束及有出处的冲突归纳，不派发模板要求的消息、不冒称身份、不缩减完整专利交付。更新前完整备份实际安装版、Git历史及文件哈希；用户之后明确要求回退时按该备份恢复通用技能，先保留待回退版本，不覆盖在途快照。原附件和提取材料留维护工作区，公开资源只保存经授权的通用约束与来源指纹。

patch 含 `expected_version` 当前版本、`summary` 实际用户意图、非空 `changes`。每项 action 为 add/replace/retire；add/replace 带完整 rule，replace 的 ID 已存在；retire 带 id。规则字段见 data-contracts.md。

例如用户明确要求长期优先保留可编辑公式，可加入 user 来源、global 范围的规则，evidence 定位到本次消息。若只要求项目甲如此，scope 必须是 `project:甲`。不要把维护文档里的示例视为已经发生的用户授权。

```text
python scripts/rules_tool.py apply --skill 当前技能目录 --patch 更新.json --dry-run
python scripts/rules_tool.py apply --skill 当前技能目录 --patch 更新.json
python scripts/rules_tool.py validate --skill 当前技能目录
```

脚本拒绝旧版本、重复 ID、缺证据或非法范围，备份旧库后原子写入并记历史；它不判断授权、语义矛盾或专业依据，应用前须审阅。失败时修复具体字段，不绕过版本检查覆盖。

## 验证和同步

先核完整现行要求和例外，再合并重复表述；已被新要求覆盖的旧句在原位置修正，不再追加一段让执行者自行猜优先级。规则ID及来源保持稳定，语义审阅不能被关键词命中或测试数量代替。

维护测试按改动选择功能组，入口为`scripts/test_groups.py`。正常直接运行一次，`--list`只在需要查看计划时使用，不作为必经步骤：

```text
python scripts/test_groups.py --changed scripts/某个已修改文件.py --workers 2 --output 检查结果.json
python scripts/test_groups.py --group formulas --group claims --workers 2 --output 检查结果.json
```

|组|范围|
|---|---|
|source|来源提取、缓存和交接证据|
|antecedents|所述、完整名词及前置链|
|claims|名称、权利要求与说明书联动|
|formulas|公式、符号、解释及数学格式|
|figures|附图说明与图号|
|pages|文档排版、渲染与页面证据|
|workflow|工作池、回执、恢复和交付|
|maintenance|规则版本、冻结清单及测试入口|

重叠组中的相同用例只运行一次。同类场景可在隔离的小组内共用准备，用命名subTest保留各场景和原断言；不合并含义不同的错误路径或跨场景共享可变状态。模块内顺序运行，跨模块最多4个独立Python进程（默认2），不用线程污染打补丁的模块，也不启动收费模型CLI。目录登记检查拒绝漏掉的新测试；缺用例、执行失败、进程错误或执行数量不足不能通过，不复用上次pass。

单独修改测试只运行该模块；参考规则/规范文字改变只运行两项原文/例外冻结覆盖测试，并由语义审阅核适用及不适用边界。仅SKILL/README等说明改变不启动运行测试，但仍核技能有效性、链接和实际变更语义，报告为未要求运行测试而非测试通过。已知实现按映射选择关联组；公共核心、未知改动或关键验收契约改变保守扩大范围，全量只在确有影响或明确要求时使用`--all`。普通专利批次不执行这些维护测试。有效检查通过即停止，只有新修改、失败或未解决问题才重验受影响范围；不重跑无关批次、旧稿渲染或历史案例。

修改影响撰写规范或流程时同步相应参考文件，再验证，最后报告版本、变动规则、范围与检查结果。不能只修改 JSON 就声称所有文档完成更新。README只展示现行用法、架构入口及当前版本摘要；旧版变更和历史验证原文归入根目录CHANGELOG.md，不再逐次堆入README或作为worker必读项。仅变更日志编辑按说明文档处理，不触发运行回归；实际代码、规则或规范仍按其影响选测。

工作区副本和安装版并存时，以实际加载路径为权威；比较版本和哈希，不用旧 ZIP 覆盖新安装版。回退通过新的版本变更恢复旧规则，保留既有历史，不直接回拨版本号。

不自动写用户长期记忆，不创建定时任务。后续增补通过再次调用此技能执行。

批处理配置变更同时同步batch-policy.json及batch-workflow.md；用户明确修改模型或交付配置时，还须同步parallel_batch.py中的对应校验及其测试，并保持batch_tool.py对旧批次的兼容，不能只改JSON导致执行被旧校验拒绝。修改普通话术不能顺带取消用户指定的Sol/high撰写、Sol/xhigh复查及修正、每案阶段有序、跨案滚动并行及逐案验收后立即将成稿直接交付到桌面同一批次文件夹根目录。内部工作分区与最终交付布局分别维护，不能为了同层交付合并各案工作目录。已运行批次保留自己的策略快照；需要改变时先按用户明确要求迁移并记录，不能将新版本静默套用到半成品。

## 版本47已授权任务内的工具缺陷

不得修改运行快照是保护旧证据，不是要求每次工具修复都由用户重新批准。已定位的内部缺陷可直接在维护副本修复、定向验证并更新通用技能；旧批次接续按[内部工具故障修复与接续](tool-fault-recovery.md)，明确兼容工具身份或恢复批次绑定，保留旧快照和旧失败证据。不能覆盖原哈希或继承通过，也不能因安装新版本就宣称旧批次已恢复。只对确实缺用户输入或授权之外的动作询问。
