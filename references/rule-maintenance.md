# 持续优化

用户可说“以后发明内容统一用……，加入技能”“这个项目才需要……”“用这份新定稿继续优化”。以当前实际调用目录为准，先读取版本。

## 收集和分级

长期明确规定记 user；只针对当前项目的修改记项目覆盖，不扩散。新案例记 example，单例差异先 candidate；用户要求通用化或多个相关案例一致支持才 active。定稿缺陷、项目数字、术语、图数不能自动变全局规则。

摘录改前/改后及来源，明确替换哪条约束；阅读旧规则做语义冲突审查。用户已授权“加入技能/以后如此”可直接更新，不重复问许可；只说改一段就只改该稿。

## 更新文件

patch 含 `expected_version` 当前版本、`summary` 实际用户意图、非空 `changes`。每项 action 为 add/replace/retire；add/replace 带完整 rule，replace 的 ID 已存在；retire 带 id。规则字段见 data-contracts.md。

例如用户明确要求长期优先保留可编辑公式，可加入 user 来源、global 范围的规则，evidence 定位到本次消息。若只要求项目甲如此，scope 必须是 `project:甲`。不要把维护文档里的示例视为已经发生的用户授权。

```text
python scripts/rules_tool.py apply --skill 当前技能目录 --patch 更新.json --dry-run
python scripts/rules_tool.py apply --skill 当前技能目录 --patch 更新.json
python scripts/rules_tool.py validate --skill 当前技能目录
```

脚本拒绝旧版本、重复 ID、缺证据或非法范围，备份旧库后原子写入并记历史；它不判断授权、语义矛盾或专业依据，应用前须审阅。失败时修复具体字段，不绕过版本检查覆盖。

## 验证和同步

至少验证一个应命中情形、一个不应命中的相邻项目，以及原有章节映射、“所述”父链、公式、删图联动。复杂更新用独立代理在临时目录执行代表性请求，检查实际结果。

修改影响撰写规范或流程时同步相应参考文件，再验证，最后报告版本、变动规则、范围与检查结果。不能只修改 JSON 就声称所有文档完成更新。

工作区副本和安装版并存时，以实际加载路径为权威；比较版本和哈希，不用旧 ZIP 覆盖新安装版。回退通过新的版本变更恢复旧规则，保留既有历史，不直接回拨版本号。

不自动写用户长期记忆，不创建定时任务。后续增补通过再次调用此技能执行。

批处理配置变更同时同步batch-policy.json及batch-workflow.md；用户明确修改模型或交付配置时，还须同步parallel_batch.py中的对应校验及其测试，并保持batch_tool.py对旧批次的兼容，不能只改JSON导致执行被旧校验拒绝。修改普通话术不能顺带取消用户指定的Sol/high撰写、Astra/high复查及修正、每案阶段有序、跨案滚动并行及桌面集中交付。已运行批次保留自己的策略快照；需要改变时先按用户明确要求迁移并记录，不能将新版本静默套用到半成品。
